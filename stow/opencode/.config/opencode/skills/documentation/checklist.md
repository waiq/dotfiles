# Documentation Quality Checklist

Use as pass/fail before publishing substantial docs.

## Purpose and Audience

- [ ] Doc type is one of: `tutorial`, `how-to`, `reference`, `explanation`.
- [ ] Audience is explicit.
- [ ] Goal/outcome is explicit.

## Structure

- [ ] Single H1 title.
- [ ] Logical H2/H3 hierarchy.
- [ ] Intro provides context in 1-3 sentences.
- [ ] Sections are skimmable (short paragraphs/lists).

## Content Quality

- [ ] No mixed-purpose drift across Diataxis types.
- [ ] Task-oriented docs include at least one minimal runnable example.
- [ ] Key pitfalls/gotchas are explicit where relevant.

## Markdown Style

- [ ] Fenced code blocks include language labels.
- [ ] Link text is descriptive (no "click here").
- [ ] List formatting is consistent.
- [ ] Tables used only when data is truly tabular.

## Metadata and Maintenance

- [ ] Front matter exists for substantive docs.
- [ ] `last_reviewed` (or `updated`) field is present.
- [ ] Owner/contact field exists for maintained docs.

## Final Gate

- [ ] Rubric score is reported.
- [ ] Score is >= 85, or top improvement actions are listed.
